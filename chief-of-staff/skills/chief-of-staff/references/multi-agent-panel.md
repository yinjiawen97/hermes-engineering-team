# 多智能体讨论的 brief 与裁决格式

配合 SKILL.md 的「召集讨论」「裁决分歧」两节。目标：几份意见收回来就能直接汇总，不用返工对齐。

## 共享证据文档

所有卡指向同一份。结构固定，只写取数和实测：

1. **被测对象** —— 地址、版本、访问方式、评审日期。
2. **观察手段的限制** —— 用什么测的、没用什么、哪些是盲区。
3. **操作清单** —— 具体做过哪些动作，用来证明只读取证。
4. **加分项** —— 实测到的优点，带证据。不写这段，报告只剩挑错，改版时会把好东西一起拆掉。
5. **缺陷清单** —— 分级，每条挂一条实测。
6. **证据文件路径与截图位置** —— 让 worker 自己去读，不要塞进 brief。

brief 里只给路径和任务，不要把证据正文贴进去：贴进去会挤占 worker 的上下文，而且你改一处证据就要改三份 brief。

## 每张卡的 brief 结构

```
## 先读这份证据（必读，不要凭印象）
<绝对路径>

## 边界
本轮只要方案，不要改代码。不要动被测系统，不要写文件到该项目。
你只负责 <这一半>，<另一半> 由另一个人负责，不要替他做。

## 任务
1. <具体问题，带已知实测值>
2. ...

## 输出要求
- 一次写完，不要分多次
- 明确标注 事实 / 推断 / 未知
- 有争议不要自己拍板，列成「待拍板」
- 不要写「建议优化」这类没有具体形状的话；要么给结构，要么给映射表，要么说不知道
```

三个约束最值钱：**标注事实/推断/未知**（否则推断会被下游当事实用）、**不许拍板**（把取舍权留在你这里）、**不许写空话**（逼出可执行形状）。

## 让双方互评

在汇总卡之前插一轮，要求各方：

1. 回答对方 brief 里点名要你确认的问题。
2. 列出「我与他真正不同的地方」+ 各自让步条件。
3. 指出对方方案里未覆盖的风险。

这一轮会把大部分表观分歧消掉，并常常让一方主动修正自己的方案。

## 裁决格式

写回每张卡，四段：

```
## 裁决：你标的 N 个未知已实测关闭
<逐条：未知 → 实测结果 → 结论>

## 你的方案需要修正一处
<哪一条、实测是什么、改成什么、代价变化>

## 采纳你的
<逐条列，让对方知道哪些判断被保留>
```

要点：

- **先关未知，再谈取舍。** 未知一关，很多争论自动消失。
- **明确说「采纳你的」**，逐条列。只写「采纳部分意见」会让对方下一轮重复已通过的论点。
- **修正要给替代方案，不是只否定。**
- **撤回要显式。** 自己早前判断错了就写「这条撤回」，不要静默改口。

## 汇总输出

给用户的汇总按：一句话判断 → 各方贡献了什么 → 我补查了什么（这是最有价值的部分）→ 分阶段计划（每项挂验收标准）→ 不做的项及理由 → 待拍板。

「不做的项」必须单列并写理由：不写的话，下一轮会有人重新捡起来讨论一遍。
